PART 1 · 사이트 기획서

내 작업물을 쌓아가는 개인 포트폴리오

작업물을 계속 업로드하며 쌓아가는 개인 포트폴리오 웹사이트. 첫 번째 프로젝트인 졸업 전시 출품작 소개부터 시작한다.

01. 기획 배경

졸업 전시에서는 작품만 놓여 있어서, 무엇을 왜 만들었고 어떤 과정을 거쳤는지까지 전하기 어렵다. 그 맥락을 웹에서 보충하고, 결과물보다 문제를 바라보고 풀어가는 '작업자'로서의 나를 보여주고 싶다. 졸업 전시를 첫 프로젝트로 시작하지만, 궁극적으로는 새 작업이 생길 때마다 업로드해 작업 이력이 쌓이는 개인 포트폴리오로 계속 쓰려고 한다. 졸업 이후에는 프리랜서로서 의뢰를 받는 창구가 되는 것이 이 사이트의 목적이다. 사이트 자체도 줄을 당겨 메뉴를 여는 물리 인터랙션으로 만들어, 첫 화면에서부터 구현 역량이 드러나게 한다.

02. 리서치 — 아티스트 포트폴리오는 어떻게 생겼나

일반적인 아티스트 포트폴리오 구성과 텍스타일 작가 사례를 찾아본 결과, 업계에는 갤러리 웹사이트와 비슷한 표준 구조가 뚜렷했다. 이 구조를 따르면 갤러리 디렉터·컬렉터가 "전문적으로 활동하는 작가"로 읽는다. 하위 페이지 사이트 지도 v2는 이 리서치를 근거로 만들었다.

업계 기본 틀

  • 필수 3페이지 — Works(작품 선별), About(Bio · Statement · CV), Contact. Contact는 About과 합치기도 한다.
  • 선택 페이지 — 뉴스·이벤트(예정 전시, 수업 등 작가를 만날 기회), 블로그(검색 노출, 작업을 둘러싼 이야기), 상점.
  • Works — 시간순·매체별·내용별 중 작가에 맞게. 시리즈로 작업하면 시리즈 단위로 나눈다. 너무 많은 작품으로 압도하지 않는다.
  • About — Bio · Statement(작가 노트) · CV. CV에는 교육, 전시, 수상·지원금, 언론, 소장처. 최신순, PDF 제공, 웹 CV에는 전화번호를 뺀다.
  • Contact — 별도 페이지와 별개로 모든 페이지 하단에 SNS와 함께 은은하게.

텍스타일 분야에서 눈에 띈 점

  • 직물을 직접 다루는 손 작업 사진이 공예 역량을 증명한다.
  • 신진 작가는 잘 기록된 졸업 작품 하나로도 초기 포트폴리오를 충분히 이끈다.
  • 자수나 패브릭 매니퓰레이션을 명시하면 차별점이 된다.
  • 프린트·패턴은 도용 위험이 있어 미공개 작업 보호 영역을 권한다.
  • 꾸준한 업데이트 — 2년간 변화 없는 사이트는 활동이 없는 것처럼 읽힌다.
  • 웹사이트는 작품의 받침대 — 형식이 작품을 방해해선 안 된다.

03. 누가 보나요 — 이용자 페르소나

이 사이트의 역할

기업 지원용이 아니라 프리랜서로서의 나를 보여주는 곳이다. 기업 지원은 별도 PDF 포트폴리오로 대응한다.

04. 디자인 방향

  • 사이트명 — 임시로 PORTFOLIO 미정
  • 정체성 — 직함은 텍스타일 디자이너 & 아티스트, 부제는 "물성과 인터랙션을 함께 다룹니다" 수준의 한 줄 미정. 메인 역할 문구의 "INTERACTION DESIGNER" 단독 표기를 이것으로 바꾼다 (03 정체성 결정).
  • 메인 콘셉트 — "작업실에 널린 원단" — 염색한 원단을 줄에 널어 말리는 텍스타일 작업실의 풍경. 내 작업물이 천장에서 내려온 줄 2개에 천으로 걸려, 들어오자마자 작품이 보인다. 진짜 천처럼 만지면 접히고 펄럭이지만, 손을 떼면 반듯하게 펴져 이미지가 읽힌다. 인터랙션은 관문이 아니라 작품 위에 덧입힌 층 — 기다리게 하거나 작품을 가리지 않는다.
  • 역할 나누기 — 레버 = 길 찾기(사이트맵), 천 = 작품 전시. 예전의 "줄을 당기면 메뉴가 열리는" 세로 글자 줄은 사이트맵 레버와 기능이 겹치고, 들어와도 작품이 하나도 안 보여 없앴다.
  • 배색 — 프리셋 비교 중 미정 — 버튼 하나로 6가지 배색을 오가며 작품 사진이 가장 돋보이는 배경을 고른다. 고른 배색은 모든 페이지에 이어진다. 작품 이미지에는 어떤 색 처리도 하지 않는다 (원단은 색이 생명).

    포인트는 어두운 배경에서 옐로 #fcad03, 밝은 배경에서 블루 #0356fc. 폰트는 Pretendard.
  • 메뉴 구성 — WORK(컬렉션·스와치) / JOURNAL(작업 일지) / ABOUT(Bio·Statement·CV) / CONTACT(연락하기). 메인에서는 사이트맵 레버로, 하위 페이지에서는 상단 메뉴로.
  • 회전 레버 → 사이트맵 — 메인 왼쪽의 직선 레버를 돌리면 화면이 함께 돌며 뒷면의 사이트맵이 올라온다. 레버를 몰라도 위의 SITEMAP 글자를 누르면 같은 전환.
  • 하위 페이지 원칙 — 작품 이미지가 주인공. 메인의 물리·유리 효과는 쓰지 않고, 여백을 넉넉하게 둔다.

작품 걸이 — 천과 줄

기능하는 일상태
걸린 작품3점. 작품마다 천장에서 내려온 줄 2개가 천 윗모서리 양쪽을 잡음. 칸마다 높이를 크게 달리해 리듬. 관리 페이지에서 "메인에 걸기"를 켠 공개 작품을 메인 순서대로 (없으면 대표 컬렉션 작품)예시
천Work 썸네일과 같은 고정 비율 (작품 4:5, 스와치 1:1) — 이미지 비율이 달라도 튀어나간 부분은 가운데 기준으로 잘림 (전체 사진은 작품 상세에서). 이미지가 없으면 X 스티치 무늬. 무늬로 먼저 걸려 있다가 이미지를 받으면 서서히 바뀜 (시작을 막지 않음). 색 보정 없이 원래 색 그대로, 접힌 곳만 음영, 뒤집힌 면은 어둡게연결 전
만지기 (드래그)천의 아무 곳이나 잡고 끌면 그 점이 따라오며 천이 늘어지고 접힘. 줄도 늘어나며 따라옴작동
복원손을 떼면 1~1.5초에 걸쳐 접힌 모서리까지 처음처럼 반듯하게 펴짐 (튕기지 않고 스르륵). 평소엔 아주 약한 바람으로 살아 있는 느낌만작동
펼쳐 보기 (탭)짧게 누르면 천이 줄에서 풀려 화면 가운데로 반듯하게 크게 펴짐 + 연도 · 기법 · 작품명 · "작품 보기 →" · 닫기. 뒤는 막으로 덮이고 다른 천은 흐려지며 조작 잠금. 바깥 클릭 · Esc · 닫기로 줄에 다시 걸림작동
당겨서 작품으로아래로 화면 높이의 30% 넘게 당기면 매듭이 포인트 색 → 놓으면 모서리가 하나씩 빠지며 천이 떨어지고 작품 상세로. 덜 당기고 놓으면 그냥 돌아감작동
다시 걸리기작품에서 돌아오면 그 천만 화면 위에서 내려와 줄에 다시 걸림 (뒤로가기 포함)작동
첫 방문 안내하단 "천을 눌러 펼쳐 보고, 끝까지 당기면 작품으로 이동해요" — 천을 처음 만지면 사라지고 다음 방문부터 안 보임작동
유리구슬잡아 끌고 던질 수 있음. 천 아래 빈 곳에서 시작. 줄 · 천에 부딪히면 출렁이고 천은 구슬 뒤로 밀림 (뚫지 않음). 구슬 안에서 천 · 격자가 굴절. 끌면 자수 방명록작동
대체 화면WebGL이 없으면 작품 이미지를 줄에 반듯하게 걸고 살짝 흔듦, 누르면 펼쳐 보기. 움직임 줄이기 설정이면 정지 상태로 걸고 누르면 바로 펼쳐 보기 (이동은 "작품 보기" 버튼)작동
스크린리더숨은 링크 목록: 메뉴 4개 + 걸린 작품 ("작품: 작품명")작동

회전 레버 · 사이트맵 · 배색

기능하는 일상태

화면 회전레버를 돌리는 만큼 화면(배경 · 천 · 줄 · 구슬 · 자수 · 작가 소개)이 레버 끝을 축으로 함께 돎. + 격자 배경은 원래 화면 밖이던 곳까지 이어짐. 상단 사이트명 · 배색 버튼 · plan-draft · 레버 라벨은 제자리작동
사이트맵 면끝까지 돌리면 뒷면의 사이트맵이 똑바로 섬. Work · Journal · About · Contact와 하위 항목 링크작동
조작 잠금돌아가는 동안에는 천 · 구슬을 잡을 수 없고, 사이트맵 링크는 다 넘어갔을 때만 눌림작동
값 기억레버 자리(메인/사이트맵)를 브라우저에 저장해 다시 열면 그대로 (사이트맵을 연 채 나가면 사이트맵으로 시작)작동

들어가기와 사용

들어가는 곳 — 숨은 입구. 메인에서 레버를 돌려 나오는 사이트맵 화면 맨 아래의 작은 admin 글자를 누른다 (또는 …/admin.html 주소를 직접). 인터랙티브 메인 화면에는 드러나지 않는다. 들어가면 페이지 섹션별 메뉴에서 목록 → 편집 → 저장.

  • 로컬 미리보기 모드 — Supabase 연결 전이라, 저장한 내용은 이 브라우저에만 남는다. 같은 브라우저로 사이트를 열면 바로 반영돼 보이지만, 다른 사람에게는 아직 예시가 보인다. 쓴 내용은 JSON 내보내기로 백업해 두면 3단계에서 그대로 옮긴다.
  • 사진 — 칸을 누르거나 끌어다 놓으면 브라우저에서 알아서 줄여서 넣는다. 휴대폰 원본 사진을 그대로 골라도 된다.
  • 글 본문 — '이미지 넣기'를 누르면 커서 자리에 사진이 들어간다.
  • 순서 · 공개 — 목록의 ↑↓로 순서를 바꾸고, 공개 스위치를 끄면 사이트에서만 숨는다.
  • 메인에 걸기 — 작품 · 스와치 편집에서 "메인에 걸기"를 켜고 "메인 순서"를 적으면 메인에 천으로 걸린다 (공개된 것 중 작은 순서부터 3점). 목록에 "메인 n" 표시.
  • 한 곳에서 고치기 — 사이트 설정의 이름·사이트명·이메일을 바꾸면 메인과 모든 하위 페이지에 함께 바뀐다.
  • 문의함 — 처리 완료 표시 · 메일로 답장 · 삭제. 실제 문의가 쌓이는 건 3단계 후 (지금은 예시).

입장 전 로그인

  • 관리 페이지를 열면 먼저 관리자 로그인(이메일 + 비밀번호) 화면이 나오고, 통과해야 편집 화면이 열린다.
  • 비밀번호 검사는 Supabase 서버가 하고, 로그인해도 관리자로 등록한 내 계정이 아니면 거절한다. 사이트 소스에는 비밀번호가 없다.
  • 화면을 가리는 건 편의일 뿐, 실제 보호는 데이터베이스 권한(RLS) — 관리자만 쓰기·비공개 읽기·사진 올리기가 된다.
  • Supabase 연결 전에는 로그인 칸이 꺼져 있고 "로컬 미리보기로 들어가기"만 된다 (이 브라우저에만 저장되므로 실제 사이트에 영향 없음).

  • 조작 안내 문구 — "줄을 끝까지 당겼다 놓으면 열려요" 등

목록을 만들며 발견한 것 (2·3단계에서 반영)

  1. 단일 정보를 담을 곳이 없다. 이름 · 이메일 · SNS · 상태 · 사이트명 · CV PDF · Bio · Statement · 메인 작가 소개는 한 벌만 있는 정보인데 Supabase 테이블에 자리가 없다 → 한 줄짜리 site_settings 테이블을 추가한다.
  2. 같은 정보가 두 군데 따로 적혀 있다. 이름과 이메일이 메인(index.html)과 하위 페이지(site.js)에 각각 있다 → 둘 다 site_settings를 읽게 해서 한 번만 고치면 되게 한다.
  3. 탭 제목에 이름이 고정돼 있다. 각 HTML의 "— KIM HANEUL"은 스크립트가 덮어쓰기 전 초기값 → 설정값 기준으로 정리.
  4. 문의함 기능이 없다. inquiries에 처리 상태 칸이 없고, 본인이 읽는 권한도 없다 → 상태 칸과 본인 전용 읽기·수정 권한 추가.
  5. 자수 방명록은 아직 저장되지 않는다. 정리 화면은 자수 2단계(저장) 뒤로.
  6. 이미지 올리는 규칙이 필요하다. 올릴 때 자동으로 긴 변 2000px · 1MB 이하로 줄이고, 저장 위치를 portfolio/works/작품id/…처럼 정해 둔다.

10. 데이터와 내용 교체

데이터 — 컬렉션 · 작품 · 저널 · CV · 문의 · 자수는 Supabase 테이블, 이미지는 Storage portfolio 버킷. 공개 표시(is_public)한 것만 사이트에 보임. 테이블 만드는 SQL은 supabase/schema.sql (SQL Editor에서 직접 실행). 메인에 걸 작품은 works.show_on_main · works.main_order — 이미 테이블을 만들었다면 파일의 alter table … add column 두 줄만 실행.

실제 내용으로 바꾸려면

  • 이름 · 이메일 · SNS · 현재 상태 · CV PDF — assets/site.js의 SITE 한 곳만 고치면 모든 하위 페이지에 반영 (메인 화면 이름·이메일은 index.html에서 따로)
  • 컬렉션 · 작품 · 스와치 · 저널 글 · CV 항목 — 지금은 assets/data.js의 예시 데이터. Supabase 연결 후에는 테이블에 행만 추가하고 is_public을 켜면 공개
  • Bio · Statement · 프로필 사진 — assets/data.js의 ABOUT
  • 이미지 — 긴 변 2000px · 1MB 이하로 줄여 Storage portfolio 버킷에 올리고 주소를 데이터에 넣기

Supabase 연결할 때 할 일

  1. Supabase 프로젝트 만들기 → SQL Editor에서 supabase/schema.sql 실행
  2. 내 관리자 계정 만들기(이메일 + 비밀번호), 아무나 가입 못 하게 끄기, 관리자로 등록하는 한 줄 실행
  3. assets/data.js 맨 위에 프로젝트 주소와 공개용 키 두 칸 채우고 푸시
  4. 관리 페이지에 로그인 → JSON 가져오기로 미리보기 때 써 둔 내용 옮기기 (사진도 자동으로 올라감)
