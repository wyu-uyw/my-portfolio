# my-portfolio
# 포트폴리오 메인 인덱스 화면 UI/UX · 구현 지침

> 사이트의 목적, 대상 독자, 메뉴별 내용 등 기획은 [plan-draft.html](plan-draft.html)에 정리되어 있다. 이 문서는 화면 UI/UX와 구현 지침만 다룬다.

## UX 원칙
- **들어오자마자 작품이 보인다.** 메인 콘셉트는 "작업실에 널린 원단" — 염색한 원단을 줄에 널어 말리는 텍스타일 작업실의 풍경. 내 작업물이 천장에 매달린 천으로 걸려 있다.
- **레버 = 길 찾기 / 천 = 작품 전시.** 메뉴 이동은 왼쪽 사이트맵 레버(와 그 위 `SITEMAP` 라벨)가 맡고, 메인의 줄은 작품을 거는 데만 쓴다.
- **인터랙션은 관문이 아니라 작품 위에 덧입힌 층.** 무엇을 하든 사용자를 기다리게 하거나 작품을 가리지 않는다. 인트로 애니메이션·로딩 연출로 시작을 늦추지 않는다.
- **진짜 천처럼, 그러나 이미지는 읽히게.** 판자처럼 움직이지 않고, 만지면 접히고 펄럭이지만 손을 떼면 반듯하게 펴진 모양으로 돌아온다.
- **작품 이미지에 색 보정·틴트·필터를 넣지 않는다.** 원단은 색이 생명.
- **모바일 우선.** 핵심 독자인 관람객이 휴대폰으로 접속하므로 터치에서도 같은 동작.

## 0. 작업 범위
- 메인 인덱스 화면 `index.html` (HTML + CSS + JS 인라인). 하위 페이지는 11장 (공통 `assets/` 공유).
- 외부 라이브러리는 cdnjs CDN: 물리엔진 **Matter.js 0.19** (줄 · 구슬), 렌더링 **three.js r128** (천, WebGL).
- 공통으로 읽는 파일: `assets/theme.css` · `assets/theme.js` (배색 프리셋, 5-1), `assets/data.js` (사이트 설정 · 작품 데이터, 13장).
- 배포: GitHub 저장소 → GitHub Pages. 빌드 도구 사용하지 않음.

## 1. 화면 구성 개요
- 전체 화면(100vw × 100vh), 스크롤 없음. 화면 자체가 하나의 물리 공간.
- 요소:
  1. 배경 (배색 프리셋의 `--bg` + 화면 전체에 촘촘히 깔린 미세한 `+` 패턴, 구슬 주변만 밝아짐 — 5-2)
  2. **작품 걸이 3개**: 작품 1점마다 천장에서 수직으로 내려온 **줄 2개**가 **천**의 윗모서리 양쪽을 잡는다 (3장)
  3. **원형 리퀴드 글래스 구슬 1개** (4장)
  4. 십자수 자수 방명록 (10장)
- 그 외: 왼쪽 세로 중앙의 **회전 레버**와 그 위 **`SITEMAP` / `MAIN` 라벨**, 레버를 돌리면 나타나는 **사이트맵 면**, 상단 고정 요소(사이트명 · 배색 프리셋 버튼 · plan-draft) — 12장.
- 화면 네 변에 보이지 않는 벽을 두어 물체가 화면 밖으로 나가지 않게 한다.

## 3. 작품 걸이 — 줄 2개 + 천 ("작업실에 널린 원단")

### 구조
- 걸리는 작품은 **3점** (모든 화면). 레버 영역(왼쪽 155px, 모바일 106px)을 뺀 폭을 3칸으로 나누고 칸 가운데에 건다.
- 작품 1점 = **줄 2개 + 천 1장**.
  - 줄: 천장 `(x, 0)`에서 천 윗변 높이까지 수직으로 내려오는 Matter.js 사슬 (원형 마디 바디 + `Constraint`, 마디 반지름 = 간격의 절반이라 틈이 없음). 천장 고정점은 약한 스프링이라 천을 당기면 줄이 늘어난다.
  - 두 줄 끝은 보이지 않는 막대(`spreader`)로 천 너비만큼 벌려 둔다 = 천 윗변이 팽팽하게 걸린 상태.
  - 천의 **윗변 양 끝 두 점**이 두 줄 끝(매듭)에 고정된다. 매듭은 작은 점(`--pin`)으로 그린다.
- 칸마다 천 윗변 높이를 크게 달리해(`TOP_RHYTHM`) 화면에 리듬을 준다.
- 같은 작품의 두 줄끼리는 충돌하지 않고, 다른 작품의 줄 · 구슬과는 부딪힌다.
- 줄은 2D 캔버스에 부드러운 곡선(색 `--rope`, 1.25px)으로 그린다.

### 천 시뮬레이션 (3D Verlet)
- 3D 베를레(Verlet) 파티클 격자. 데스크톱 가로 18칸, 모바일 10칸, 세로 = 가로 × 천 비율. 좌표: x 오른쪽, y 아래(화면 px), z 화면 앞쪽 — 깊이가 있어 실제로 접히고 뒤집힌다.
- 제약: 구조(상하좌우) · 전단(대각선) · 굽힘(한 칸 건너뛰기). Matter.js와 같은 고정 서브스텝 루프에서 서브스텝마다 반복 해결.
- **천 무게**: 서브스텝마다 두 줄 끝에 아래로 힘(`weight`). **천을 당기면** 천이 늘어난 장력이 줄 끝을 끌어당겨(`tug`) 줄이 늘어나며 따라온다.
- **묶음(tether)**: 손을 뗀 뒤에는 어느 점도 두 매듭에서 반듯할 때 거리의 1.12배보다 멀어지지 못한다. 늘어난 만큼을 **속도 없이**(pos · prev 함께) 거둬들여 고무처럼 휙 튕기지 않는다.
- **복원력** (가장 중요): 모든 점이 "두 줄 끝에 반듯하게 걸린 자리"(윗변 = 두 줄 끝을 잇는 선, 그 수직 아래로 펼쳐짐)로 다가간다. pos와 prev를 함께 옮겨 속도를 만들지 않으므로 출렁이며 오가지 않고 스르륵 펴진다.
  - 손을 뗀 뒤: 복원력 `restore` + 중력 0.3배(`gravityFree`). 접힌 자락이 중력에 눌려 접힌 채 남지 않고 모서리까지 펴진다 (~1.5초).
  - 잡고 있는 동안: 복원력은 아주 약하게(`restoreHeld`), 중력은 그대로라 끄는 동안 자연스럽게 처진다.
- **바람**: 위치 · 시간에 따라 천천히 흐르는 물결(사인 몇 개를 겹친 노이즈, 아주 느린 세기 변화). 주로 앞뒤(z)로, 옆으로 조금. 살아 있는 느낌만 — 이미지를 가릴 만큼 펄럭이지 않는다.
- 섬유별 물성(실크 · 울 등)은 두지 않는다. 모든 천이 같은 물성.

| `CLOTH` | 값 | 뜻 |
|---|---|---|
| `cols` / `colsMobile` | 18 / 10 | 가로 격자 수 |
| `gravity` | 1800 | px/s² |
| `iterations` | 4 | 서브스텝마다 제약 반복 (높을수록 덜 늘어남) |
| `shear` · `bend` | 0.9 · 0.08 | 전단 · 굽힘 강성 (구조 = 1) |

### 렌더링 (three.js)
- WebGL 캔버스 1개(`#cloth`), 화면 픽셀과 1:1인 정사영 카메라 (화면 좌표 (x, y) → three 좌표 (x, −y)).
- 매 프레임 BufferGeometry 위치 갱신 + 법선 재계산.
- 셰이더(직접 작성):
  - **정면을 보는 면은 밝기 계수가 정확히 1** → 원래 색 그대로. 접혀서 비스듬한 면만 은은한 방향광으로 어두워져 입체감이 생긴다.
  - **뒤집힌 면**(`gl_FrontFacing`)은 원단 뒷면처럼 흐리게(밉맵 바이어스) · 어둡게 · 채도를 조금 빼서.
- **색 정확도**: 텍스처는 인코딩 변환 없이 sRGB 값을 그대로 화면에 낸다 (색 보정 · 톤매핑 없음). 밉맵 + 비등방 필터. 긴 변 최대 1024px로 줄여 올린다.
- **천 비율 = Work 페이지 썸네일과 같은 고정 비율** (작품 4:5, 스와치 1:1 — `CONFIG.hang.ratio` · `ratioSwatch`). 업로드한 이미지 비율이 제각각이어도 천 모양은 같고, 튀어나간 부분은 **가운데 기준으로 잘린다**(CSS `object-fit: cover`와 같은 방식, `setClothImage`). 전체 사진은 작품 상세에서 본다. 크기는 칸 너비 · 최대 높이(화면 높이 45%) 안에서 크게.
- 이미지가 없으면 하위 페이지 이미지 자리와 같은 **X 스티치 무늬**를 캔버스로 만들어 텍스처로 건다 (배색을 바꾸면 무늬 색도 다시).
- **이미지를 받는 동안 시작을 막지 않는다**: 천은 X 스티치 무늬로 먼저 걸려 있다가, 이미지를 받으면 서서히 바뀐다(`map2` + `mixT` 크로스페이드). 비율이 고정이라 이미지가 늦게 와도 천 크기는 바뀌지 않는다 (스와치가 걸리면 그 걸이만 정사각으로 한 번 다시 건다).
- 천 그림자: 캔버스 전체에 `drop-shadow(0 14px 18px var(--cloth-shadow))` 한 번.

### 레이어 순서
배경 < `+` 격자 < 자수 캔버스 < **천(WebGL)** < 줄 · 매듭(2D 캔버스) < 유리 구슬 → 구슬이 천 위를 지나가면 천도 유리 안에서 굴절 · 흐림 처리되어 보인다.

### 구슬과 천
- 구슬은 천보다 살짝 앞(`ballDepth` × 반지름)에 있는 구로 계산한다. 구 안으로 들어온 천 점을 구 표면으로 밀어내 → 천이 구슬 뒤로 밀리며 출렁이고, 구슬을 뚫고 지나가 보이지 않는다.
- 천을 밀어낸 만큼 구슬도 조금 느려진다(`ballPush`).

### 천 인터랙션 — 같은 천 위에서 세 가지
1. **드래그 = 만지기**: 천의 보이는 삼각형 안을 누르면 그 삼각형에서 가장 가까운 점을 잡고, 그 점이 포인터를 따라간다 (조금 앞으로 들림). 천이 늘어지고 접히고, 줄이 늘어나며 따라온다. 놓으면 움직이던 속도가 이어지다 복원력으로 펴진다.
2. **탭 = 펼쳐 보기** (6px 미만 · 250ms 미만):
   - 천이 줄에서 풀려 화면 가운데 위쪽으로 나오며 **반듯하게 펴지고 커진다** (천 점들을 평평한 목표 격자로 보간, `unfoldMs`).
   - 아래에 연도 · 기법 태그, 작품명, **"작품 보기 →"** 버튼, 닫기.
   - 바깥 클릭 · Esc · 닫기 → 지금 줄 끝에 반듯하게 걸린 자리로 돌아가 다시 걸린다 (`foldMs`).
   - 펼쳐 보는 동안: 뒤를 반투명 막(`#unfold-dim`, `--overlay-bg`)으로 덮고, 다른 천은 셰이더에서 흐려지며(`fade`), 화면 전체를 덮는 투명한 층(`#unfold`)이 다른 천 · 구슬 · 레버 조작을 막는다.
3. **아래로 끝까지 당기기 = 작품으로 이동**:
   - 잡은 자리에서 화면 높이의 30%(`pullOpen`) 이상 아래로 당기면 두 매듭이 `--accent` 색으로 바뀐다 = "놓으면 열린다".
   - 그 상태로 놓으면 매듭에서 모서리가 하나씩(0.14초 간격) 톡톡 빠지며 천이 떨어지고, 이어서 화면을 배경색으로 덮으며 `work-detail.html?id=…`로 이동. 당기던 탄력으로 위로 튀지 않게 떨어지는 순간 속도를 비운다.
   - 임계값 전에 놓으면 그냥 돌아간다.
   - **메인으로 돌아오면 그 천만 화면 위에서 내려와 다시 줄에 걸린다** (`sessionStorage["hung-from"]`, 뒤로가기 bfcache 포함).
- 입력 우선순위: 레버 영역 → 유리 구슬 → 천.
- **첫 방문 안내**: 하단 "천을 눌러 펼쳐 보고, 끝까지 당기면 작품으로 이동해요". 천을 처음 만지면 사라지고 `localStorage["hint-cloth"]`에 기억(try/catch).
- 하위 페이지에서 사이트명(로고)으로 돌아오면(`sessionStorage.rehang`) 모든 줄이 같은 각도로 들렸다가 진자처럼 흔들리며 내려온다.

### 걸리는 작품 (데이터)
- `DB.mainWorks(3)`: **공개(`is_public`) + 메인에 걸기(`show_on_main`)** 작품을 **`main_order`** 순으로 최대 3점. 하나도 없으면 대표 컬렉션의 작품으로 대신한다. 스와치도 걸 수 있다 (type과 무관).
- 관리 페이지의 작품 · 스와치 편집에서 "메인에 걸기" 스위치와 "메인 순서"로 고른다 (13장).
- 작품을 기다리지 않고 천부터 건다. 작품 데이터 · 이미지는 받는 대로 붙는다.

## 4. 리퀴드 글래스 구슬
- 페이지 로드 직후 **걸린 천들 아래 빈 바닥 쪽(오른쪽)** 에서 시작한다 → 처음부터 줄 사이에 끼어 움직임이 막히지 않는다.
- 물리: Matter.js 원형 바디. 바닥/좌우 벽 · 줄과 충돌.
- 드래그: 구슬을 **클릭(터치) 후 홀드한 상태로 드래그**하면 화면 내 자유 이동. 위치를 덮어쓰지 않고 스프링 `Constraint`로 끌어, 이동 중에도 충돌 판정이 유지된다. 놓으면 그 순간의 속도로 던져진다.
- 터널링 방지: 프레임당 서브스텝 8회 + 구슬 최대 속도 제한.
- 구슬이 줄과 부딪히면 줄이 밀려나며 흔들리고, 줄 위에 걸칠 수 있다. 천과의 충돌은 3장.
- 구슬이 줄과 겹친 채로 생성/리사이즈되면 겹침이 풀릴 때까지 줄과의 충돌을 끈다(ghost).

## 5. 리퀴드 글래스 렌더링
- 물리 바디 위치에 동기화되는 원형 DOM 요소 `#glass`.
- `backdrop-filter: blur + saturate + brightness`로 뒤가 비친다. 블러를 약하게 두어 뒤의 `+` 패턴 · 천이 흐려져 사라지지 않고 **휘어 보이게**.
- 반투명 `--glass-tint` + 얇은 테두리 `--glass-border`(잡으면 `--glass-border-held`), inset box-shadow의 흰 하이라이트, 바깥 그림자 `--glass-shadow`.
- 가장자리 굴절: 방사형 변위 맵을 만든 SVG `feDisplacementMap`을 backdrop에 적용 (Chromium). 지원하지 않는 브라우저는 일반 블러로 대체.
- 이동 속도에 따라 하이라이트가 반대쪽으로 밀리고, 드래그 중에는 살짝 커지며 물방울처럼 눌린다.

## 5-1. 배색 프리셋 (색 토큰)

| Blue (기본) | `#0356fc` | `#ffffff` | `#fcad03` | 처음 배색 |

- 밝은 배경(Linen · Greige · Gallery)은 노랑 대비가 낮아 포인트를 블루로. 유리 테두리는 `rgba(0,0,0,.12)` + 흰 하이라이트, 그림자 `rgba(0,0,0,.15)`. 구슬 근처 `+`는 진해지는 방향(`--plus-bright`). 메인 이름 외곽선은 바탕색.
- 버튼(메인 우측 상단, 하위 페이지 푸터)에 지금 프리셋 이름이 보이고, 누를 때마다 다음 프리셋으로.
- 선택은 `localStorage.theme`에 저장되어 모든 페이지에 이어진다. 각 페이지 `<head>`의 `assets/theme.js`가 그리기 전에 `<html data-theme="…">`를 붙여 깜빡임을 막는다(기본 Blue는 속성 없음). 예전 저장값 `inverse`는 `white`로 이어받는다.
- 메인 캔버스(줄 · `+` 밝아짐 · 자수 · X 스티치 텍스처)는 색을 읽어 그리므로 프리셋이 바뀌면 다시 그린다. `color-mix()` 토큰은 `cssColor()`가 rgb로 풀어 캔버스에 넘긴다.

## 5-2. + 패턴 배경
### 구성
- 화면 전체에 `+` 기호를 촘촘한 격자로 배치.
  - 간격: 모든 화면에서 24px (자수 격자와 공유하므로 모바일도 동일)
  - 격자 기준점은 **화면 중앙**. 중앙 셀이 (0,0)이고, 각 셀의 `+` 중심 = 화면 중앙(픽셀 중앙 정렬) + (col, row) × 24px.
  - `+` 크기 7px, 선 두께 1px. 폰트 문자가 아닌 선 2개로 그려서 선명하게.
- 평소에는 `--plus-dim` 투명도로 거의 안 보이게 깔려 있다.
- 원형 글라스 구슬의 **중심 위치를 기준으로 반경 안의 `+`가 밝아지면서(밝은 배경에선 진해지면서) 크기도 커진다.**
  - 범위: 구슬 반지름의 약 2.5배
  - 밝기: 중심에서 멀어질수록 부드럽게 dim으로 감소 (smoothstep 감쇠)
  - 크기: 밝기와 같은 smoothstep 값으로 함께 변한다. 중심에서 최대 약 2.2배, 선 두께도 1px → 약 1.6px.
  - 구슬 위치를 lerp(약 0.15)로 살짝 늦게 따라와 잔상처럼 부드럽게.

### 구현 방식 (성능 우선)
- **dim 레이어**: `--plus-dim` 색의 `+` 패턴 (SVG 타일을 mask-image로 반복).
- **bright 레이어**: `<canvas>` 1장. 구슬 주변 범위 안의 `+`만 `--plus-bright` 색으로 그리고, 지난 프레임에 그린 영역만 지운다. 멈춰 있으면 다시 그리지 않는다.
- 두 레이어의 격자 위치는 `--grid-ox`, `--grid-oy`로 화면 중앙 기준에 맞춘다.
- 조절값: `GLOW` 상수 (`range`, `follow`, `maxScale`).

### 레이어 순서 (z-index)
- 배경색 < `+` 패턴(dim, bright) < 자수 캔버스 < 천(WebGL) < 줄 · 매듭 < 리퀴드 글래스 구슬 < 펼쳐 보기 막(이때만 천 캔버스가 그 위로)
- 위 레이어들과 하단 작가 소개, 사이트맵 면은 모두 회전판 `#world` 안에 있다. 그 위에 상단 사이트명(z 1) < 레버(z 4) < 레버 라벨 · 배색 프리셋 · plan-draft(z 5) < 펼쳐 보기 정보층(z 9) < 페이지 이동 덮개(z 30)가 회전판 밖에 고정된다.

## 6. 반응형 / 접근성 / 성능 / 대체 화면
- 리사이즈 시 벽, 작품 걸이(줄 · 천), 구슬 크기를 프레임당 1회로 묶어 다시 만든다.
- 모바일 터치 드래그 지원, 드래그 중 스크롤/새로고침 제스처 방지 (`touch-action: none`). 모바일은 천 격자를 10칸으로 줄이고 천을 칸에 더 꽉 차게.
- 성능: 60fps 목표, requestAnimationFrame 루프 1개(고정 서브스텝). 탭이 비활성이면 정지. devicePixelRatio 최대 2.
- **WebGL 미지원**: 작품 이미지(같은 썸네일 비율로 잘림, 없으면 X 스티치 무늬)를 두 줄 끝에 반듯하게 DOM으로 걸고 CSS로 살짝 흔든다. 누르면 펼쳐 보기(같은 자리에 이미지를 크게), 당기기 대신 "작품 보기" 버튼.
- **`prefers-reduced-motion`**: 물리 · 바람 · 흔들림 없이 반듯하게 걸린 정지 상태. 천을 누르면 바로 펼쳐 보기(애니메이션 없이), 이동은 "작품 보기" 버튼.
- **접근성**: 시각적으로 숨긴 링크 목록 두 개 — 메뉴(Work · Journal · About · Contact)와 **걸린 작품 목록**("작품: 작품명" → 작품 상세). 레버와 `SITEMAP` 라벨 버튼은 키보드로 조작. 펼쳐 보기는 `role="dialog"`, 열리면 닫기 버튼에 포커스, Esc로 닫힘.

## 10. 십자수 자수 방명록

### 원칙
- 기존 물리, 작품 걸이(줄 · 천), 리퀴드 글래스, + 패턴 밝아짐 효과는 **수정하지 않는다.**
- 자수 기능은 별도 모듈(함수/섹션)로 분리해서 추가한다.
- 1단계 완료 후 브라우저에서 확인 → 커밋 → 2단계 진행.

### 컨셉
화면에 깔린 + 격자를 십자수 천(아이다 천)으로 보고, 리퀴드 글래스 구슬을 바늘처럼 끌고 다니면
지나간 자리의 + 가 흰 실로 놓인 X 스티치로 바뀐다. 방문자들이 남긴 자수가 쌓여 하나의 천이 된다.

### 1단계: 화면 위 자수 (로컬)

#### 격자 기준
- 자수 격자는 기존 + 패턴 격자와 **정확히 일치**해야 한다.
- 모든 화면 크기에서 격자 간격을 24px로 통일 (기존 모바일 20px 설정을 24px로 변경).
- 셀 좌표는 **화면 중앙을 (0,0)으로 하는 정수 (col, row)** 로 관리한다.
  → 화면 크기가 달라도 같은 자수가 같은 자리에 보이게 하기 위함. 화면 밖 셀은 그리지 않을 뿐 데이터는 유지.
- + 패턴의 background-position도 화면 중앙 기준으로 맞춰서 셀 좌표와 어긋나지 않게 할 것.

#### 스티치가 놓이는 조건
- 사용자가 구슬을 **홀드-드래그하는 동안에만** 놓인다. (낙하·굴러감·던진 후 이동 중에는 놓이지 않음)
- 구슬 중심 기준 반경 = 구슬 반지름 × 0.35 안에 들어온 셀이 스티치 대상.
- 속도 반영 (손맛):
  - 느리게 움직이면 반경 안 셀이 모두 채워짐
  - 빠르게 움직일수록 확률적으로 건너뛰어 듬성듬성해짐 (속도에 비례해 채움 확률 감소, 최소 20%)
- 프레임 사이 이동 거리가 길면 이전 위치~현재 위치를 선형 보간해서 경로 중간 셀도 판정 (빠르게 끌어도 선이 끊기지 않게).
- 이미 스티치된 셀은 다시 놓이지 않음.

#### 스티치 표현
- 별도 `<canvas>` 레이어를 추가. 레이어 순서:
  배경색 < + 패턴(dim/bright) < **자수 캔버스** < 천 · 줄 < 리퀴드 글래스 구슬
  → 자수가 구슬 뒤에 있으므로 구슬 안에서 자수도 굴절되어 보여야 한다.
- 스티치 = 셀 안에 그리는 X 모양 실 두 가닥.
  - 먼저 셀 아래의 + 를 가리도록 배경색(`--bg`)으로 작은 사각형을 칠한 뒤 X를 그린다.
  - 크기: 셀의 약 70%, 선 두께 1.5px, 선 끝 둥글게 (lineCap: round), 색 `--stitch`.
  - 실 느낌: 각 가닥의 끝점을 ±0.6px 랜덤 흔들림, 투명도 0.85~1 랜덤. 실 가운데가 살짝 밝고 가장자리가 어두운 미세한 그라데이션이면 더 좋음.
  - 손바느질 순서처럼 `/` 를 먼저 그리고 이어서 `\` 를 그리는 애니메이션 (각 약 80ms).
- 캔버스는 devicePixelRatio 대응. 새 스티치만 증분으로 그리고, 리사이즈 시에만 전체 다시 그림.
- 스티치 데이터는 메모리의 Map(`"col,row"` → { col, row, createdAt })에 보관.
- 기존 + 밝아짐 효과는 자수 위에도 자연스럽게 겹쳐 보여도 무방.
- **불투명도 최대치 80%**: 자수(실과 + 가림 사각형 포함) 전체를 최대 0.8 불투명도로 그려, 겹친 메인 화면 텍스트가 묻히지 않게 한다 (`STITCH.opacity`).
- **약 10초 뒤 사라짐**: 스티치는 놓인 지 6초부터 4초 동안 서서히 옅어져 10초에 사라진다 (`STITCH.lifeMs`, `STITCH.fadeMs`). 사라진 셀은 Map에서 지워져 다시 수놓을 수 있다.

#### 기타
- `prefers-reduced-motion`이면 그리기 애니메이션 없이 즉시 표시.
- 자수는 물리에 영향을 주지 않는다 (충돌 바디 없음).

#### 구현 메모
- 코드의 "십자수 자수 방명록" 섹션에 분리. 조절값은 `STITCH` 상수 (`reach`, `size`, `width`, `jitter`, `fastSpeed`, `minFill`, `strokeMs`).
- 채움 확률 = max(0.2, 1 − 프레임당 이동량 / 40px). 한 프레임 안에서 셀마다 한 번만 판정한다.
- 실의 흔들림·투명도 난수는 셀 좌표로 고정(시드)해서, 리사이즈로 다시 그려도 같은 모양이 나온다.
- 실 그라데이션은 같은 선을 두 번(옅고 두꺼운 가장자리 → 밝고 얇은 가운데) 그려 표현한다.

#### 1단계 확인
- [ ] 구슬을 드래그할 때만 지나간 자리에 X 스티치가 놓인다
- [ ] 천천히 끌면 촘촘, 빠르게 끌면 듬성듬성
- [ ] 스티치가 + 격자와 정확히 같은 위치에 놓인다 (리사이즈 후에도)
- [ ] 구슬 안에서 스티치가 유리에 굴절되어 보인다
- [ ] 스티치가 약 10초 뒤 서서히 옅어지며 사라진다
- [ ] 스티치와 겹쳐도 메인 화면 텍스트가 읽힌다 (자수 불투명도 최대 80%)
- [ ] 기존 기능이 전부 그대로 동작한다

## 11. 하위 페이지 (사이트 지도 v2)
> 사이트 지도 수정 지침서 v2로 이전 사이트 지도를 대체한다.

### 설계 근거 (리서치)
v2는 아티스트·텍스타일 작가 포트폴리오 리서치를 바탕으로 했다. 지침의 각 항목이 왜 그런지는 아래를 따른다.
- **업계 표준 구조**: 필수 3페이지 Works · About(Bio/CV) · Contact + 선택 페이지(블로그·뉴스). 이 구조를 따라야 갤러리·컬렉터가 '활동하는 작가'로 읽는다 → Work / Journal / About / Contact.
- **Works**: 시리즈 단위로 나누는 방식이 일반적, 너무 많은 작품으로 압도하지 않기 → 컬렉션 단위 + 기법 필터, 한 줄 2~3개, 대표 컬렉션 1개 강조.
- **About**: Bio · Statement · CV 세 덩어리. CV에는 교육·전시·수상과 지원금·언론·**소장처**, 최신순, PDF 제공, 웹 CV에는 전화번호 제외.
- **Contact**: 별도 페이지와 별개로 모든 페이지 하단에 SNS와 함께 은은하게 노출.
- **텍스타일**: 손 작업 사진이 공예 역량을 증명 → 제작 과정에 손 작업 필수. 잘 기록된 졸업 작품 하나로도 초기 포트폴리오를 이끈다 → featured 컬렉션. 자수·**패브릭 매니퓰레이션**을 명시하면 차별점 → 기법에 Manipulation 추가, 작품 상세에 기법을 한글로 명시.
- **도용 위험**: 프린트·패턴은 미공개 작업 보호 영역이 권장됨 → 2차 과제 (클라이언트 비밀번호 금지, Auth/서명 URL).
- **꾸준한 업데이트**: 오래 변화 없는 사이트는 활동이 없어 보임, 블로그는 검색 노출과 작업 이야기에 도움 → Journal 날짜를 눈에 띄게, 글·작품마다 검색용 설명(meta description) 설정.
- **형식이 작품을 방해하지 않기**: 웹사이트는 작품의 받침대 → 메인은 인터랙티브, 하위 페이지(특히 작품 상세)는 효과 최소화.

### 변경 요약
1. About을 Bio / Statement / CV 세 섹션으로 재구성
2. Work 정리 기준을 '컬렉션(시리즈)' 단위로 변경, 기법은 필터로 유지
3. Work 상세에 '손 작업(제작 과정) 사진' 섹션 필수화
4. 모든 페이지 하단에 연락처·SNS 상시 노출
5. 하위 페이지는 인터랙션 최소화 — 작품 이미지가 주인공
6. 웹에 노출되는 CV에서 전화번호 제외
7. 미공개 작업 보호 영역은 2차 과제로 보류

### 파일 구성
| 파일 | 역할 |
|---|---|
| `assets/site.css` | 하위 페이지 공통 스타일 (색 변수·반전 배색, + 격자, 헤더·푸터, 탭·칩·카드, 이미지 프레임, 라이트박스, CV) |
| `assets/site.js` | `SITE` 설정(이름·이메일·SNS·상태·CV), 헤더/푸터 주입, `<title>` 형식, 라이트박스, 배색 전환, 유틸(`esc`, `param`, `media`, `zoomable`, `paragraphs`, `formatDate`, `setTitle`) |
| `assets/data.js` | 데이터 계층 `DB.*`, 라벨 `LABELS`, 예시 데이터 `SAMPLE`, About 고정 내용 `ABOUT` |
| `supabase/schema.sql` | 테이블 생성 + RLS + Storage 버킷 SQL (SQL Editor에서 직접 실행) |
| `work.html` · `collection.html` · `work-detail.html` | Work 목록(탭) / 컬렉션 상세 / 작품 상세 |
| `journal.html` · `journal-post.html` | 저널 목록 / 글 |
| `about.html` · `contact.html` | About(Bio·Statement·CV) / Contact |

- 각 페이지는 `<body data-page="work" data-title="Work">`로 현재 메뉴와 제목을 표시하고, `site.js` → `data.js` 순서로 불러온 뒤 페이지 스크립트를 실행한다.
- 메인 `index.html`은 단일 파일 그대로 (공통 `assets/`를 쓰지 않음).

### 공통 요소 (모든 하위 페이지)
- 디자인 언어 유지: 배색 프리셋 토큰(5-1), Pretendard 300, 미세한 + 격자 (배색 프리셋 버튼은 푸터)
- 좌측 상단: **사이트명(로고)** — 메인 좌측 상단과 같은 사이트명(`site_title`) → 클릭 시 메인으로. 메인은 작품 걸이의 줄들이 진자처럼 흔들리며 다시 매달리는 연출로 맞는다 (`sessionStorage.rehang`).
- 우측 상단: 고정 네비게이션 Work · Journal · About · Contact. 모든 페이지에서 같은 위치·형식, 현재 페이지는 `aria-current="page"` + 노랑 밑줄. 컬렉션·작품 상세는 Work, 글 상세는 Journal로 표시.
- **하단 푸터 (모든 페이지 필수)**: 이메일, SNS 링크(`SITE.sns` 배열), © 이름 연도
- `<title>`은 **"페이지명 — 이름"** 형식. 목록 페이지는 HTML에 고정, 상세 페이지는 불러온 뒤 `setTitle(작품명)`으로 "작품명 — 이름".

### 하위 페이지 디자인 원칙
- 메인의 물리·글래스 효과는 하위 페이지에 넣지 않는다.
- + 격자 배경은 유지하되 dim 상태로만, 구슬 따라 밝아지는 효과 없음.
- 작품 이미지 위·주변에 장식 요소를 두지 않는다. 여백을 넉넉하게.
- 허용되는 인터랙션: 이미지 페이드인, 호버 시 살짝 확대, 라이트박스(이미지 크게 보기).
  - 페이드인: `<img>`가 불러와지면 0.6초 동안 나타남 (`.media.loaded`).
  - 호버 확대: 테두리 상자(`.frame`, `.zoom`) 안에서만 1.03배. 상자 밖으로 넘치지 않는다.
  - 라이트박스: `zoomable()`로 만든 이미지를 누르면 열림. 같은 그룹(대표/과정/갤러리/스와치 등) 안에서 ←/→ 이동, Esc·바깥 클릭·✕로 닫기, 포커스는 라이트박스 안에 가두고 닫으면 원래 자리로.
  - 그 외 페이지 간 페이드아웃 등은 두지 않는다 (페이지 첫 진입 0.5초 페이드인만 유지 — 메인의 줄 끊김 전환과 이어지게).
  - `prefers-reduced-motion`이면 페이드·확대 없음.
- 한 화면에 작품을 너무 많이 나열하지 않는다 (컬렉션 목록은 한 줄 2~3개).
- 이미지는 웹용으로 최적화 (긴 변 2000px 이하, 1MB 이하 권장, lazy loading). `<img>`는 `loading="lazy" decoding="async"`.

### 페이지별 구현 메모
- **Work 목록**: 탭(`?tab=swatch`)과 기법 필터(`?tech=weave,dye`)가 주소에 남는다. 기법은 선택한 것 중 하나라도 쓰면 표시(OR).
  - Collections 탭: 컬렉션 안 작품 중 하나라도 선택한 기법을 쓰면 그 컬렉션을 표시. `is_featured` 컬렉션은 맨 위에 크게(이미지 16:10 + 제목), 나머지는 한 줄 2~3개 카드. 한 줄 설명은 `concept` 첫 문단의 첫 문장.
  - Swatch 탭: 정사각 썸네일 그리드. 누르면 라이트박스로 확대 + 기법·섬유·크기·메모 표시, 스와치끼리 ←/→.
  - 탭은 ←/→ 키로도 전환.
- **컬렉션 상세**: 제목·연도·컨셉(빈 줄로 나뉜 문단) + 대표 이미지, 포함된 작품 카드, 이전/다음 컬렉션(`sort_order` 순).
- **작품 상세**: 대표 이미지 → 기본 정보(소속 컬렉션 링크, 기법 태그는 Work 필터로 연결) → 소재 정보(기법은 한글) → 작업 설명 → 제작 과정(`process_images`, 단계: sketch/pattern/sample/handwork, 비어 있으면 "준비 중" 문구 — 섹션은 항상 표시) → 갤러리(`detail: true`는 정사각 + DETAIL 표시) → 같은 컬렉션의 다른 작품 → 컬렉션으로 돌아가기 (스와치는 Swatch 탭으로).
- **Journal**: 날짜를 크게(22px) 맨 앞에. 썸네일은 `images[0]`. 글 본문은 빈 줄로 문단 구분, `[[image:0]]`만 있는 줄은 `images[0]` 자리 — 본문에 쓰지 않은 이미지는 글 끝에 붙는다. 관련 작품·컬렉션 카드는 있을 때만.
- **SEO**: 작품·컬렉션·글 상세는 불러온 뒤 `setTitle(제목, 설명)`으로 `<title>`과 `meta description`(160자)을 바꾼다. 설명은 작품 설명·컨셉 첫 문단, 글 요약.
- **About**: 상단 앵커(Bio · Statement · CV, 부드러운 스크롤). Bio·Statement는 `data.js`의 `ABOUT`. CV는 `cv_items`를 섹션별로 묶어 최신순(예정 → 연도 내림차순 → `sort_order`), `note`는 배지(개인전/단체전/워크숍/외주 등), `is_upcoming`은 노랑 [upcoming] 배지, `link`가 있으면 ↗ 링크. 전화번호 필드는 없다.
- **Contact**: 문의 유형에 '전시' 추가. 저장소 연결 전에는 작성 내용을 채운 메일 앱으로 대체.

## 12. 좌측 회전 레버 (메인 인덱스)

### 원칙
- 기존 물리, 작품 걸이, 리퀴드 글래스, + 패턴, 자수 기능은 수정하지 않는다.
- 레버는 별도 모듈로 추가하고, 값 변화는 `onLeverChange(value)` 하나로만 외부에 전달한다.
  (무엇을 조절할지는 나중에 이 함수에 연결)

### 형태
- 극도로 간소화한 다이얼: **흰색 직선 하나**가 회전하는 것으로만 표현.
  - 길이 77px (모바일 58px), 두께 1.5px, 끝 둥글게, 색 `--lever` — 처음 지침(64/48px)보다 20% 키움
  - 회전 중심(피벗): 직선의 **아래쪽 끝**. 피벗 위치에 지름 4px 흰 점 하나.
- 위치: 화면 왼쪽에서 48px(모바일 24px) 떨어진 지점, 세로 중앙.
  창 크기가 바뀌어도 이 간격 유지 (position: fixed).
- 보조 표시 (아주 옅게, 생략 가능):
  - 회전 범위를 따라 반원 궤적 위에 점 3개 (0°, 90°, 180° 위치), 투명도 0.25
  - 드래그 중에만 궤적 점들이 0.5로 밝아짐
- **사용법 힌트 — 곡선 화살표**: 선 끝 바깥쪽 궤도(반지름 = 길이 + 10px)에, 쉬는 자리의 반대편으로 돌릴 방향을 가리키는 짧은 호 화살표.
  - 메인(0°)에서는 시계 방향(현재 각도 +16° ~ +62°), 사이트맵(180°)에서는 반시계 방향(현재 각도 −16° ~ −62°). 레버와 함께 움직이고, 남은 회전이 짧으면 숨긴다.
  - 두께 1.2px, 투명도 0.45 (호버·드래그 중 0.8), 색 `--lever`.
- 작품 걸이는 레버 영역(왼쪽 155px, 모바일 106px)을 피해서 배치한다.

### 레버 라벨 — `SITEMAP` / `MAIN`
- 레버 바로 위에 작은 텍스트 버튼 `#lever-label`. 레버를 돌리는 법을 몰라도 글자는 눌러 보기 때문.
- 메인에서는 `SITEMAP`, 사이트맵 쪽으로 넘어가면 `MAIN`. `aria-label`도 "사이트맵 열기" / "메인으로 돌아가기".
- 누르면 `commitLever()` — 레버를 돌린 것과 같은 전환 ('탁' 넘어가기 · 저장 포함).
- 회전판 밖 고정 레이어(z 5)라 화면이 돌아도 제자리. 11px, 자간 0.24em, `--text-soft`(호버 `--text`). 글자 시작이 레버 선과 같은 x에 오도록 잡기 여백만큼 왼쪽으로 당긴다.

### 동작
- 기본 상태: **수직으로 서 있음** (12시 방향) = value 0
- 드래그하면 피벗을 중심으로 **오른쪽으로 반원**을 그리며 회전
  - 범위: 12시(0°) → 3시(90°) → 6시(180°)
  - value = 각도 / 180 → 0 ~ 1
  - 범위 밖으로 끌어도 0° 또는 180°에서 멈춤 (clamp)
- 각도 계산: 포인터 위치와 피벗의 atan2로 구함. 선 자체뿐 아니라 피벗 반경 96px(크기에 맞춰 80px에서 20% 키움) 안 어디를 잡아도 드래그 가능 (얇은 선을 정확히 잡기 어렵기 때문).
- 움직임 느낌: 포인터 각도를 그대로 쓰지 말고 lerp(0.25)로 따라오게 해서 묵직한 아날로그 다이얼 느낌.
- 드래그 중 커서: `grabbing`. 호버 시 선이 살짝 굵어짐(2px).
- ~~놓으면 그 위치에 머문다.~~ → **중간 정지 금지, 두 자리 스위치** (수정 요청 반영)
  - 레버는 0°(메인)와 180°(사이트맵) 두 자리에만 머문다. 중간 각도에서 화면을 멈춰 조작하는 구멍을 막기 위함.
  - 쉬는 자리에서 **60°**(`LEVER.snap`) 이상 돌리면 손을 떼지 않아도 자동으로 반대편 끝까지 '탁' 넘어간다 (드래그 종료).
  - 60° 전에 놓으면 쉬던 자리로 되돌아간다.
  - 넘어가거나 되돌아갈 때는 스프링(`spring` 0.09, `damping` 0.78)으로 움직이고, 끝에 부딪히면 살짝 튕긴다(`bounce` 0.3) — 손에 걸리는 '탁' 느낌.
- 마지막 자리(0 또는 1)를 localStorage에 저장해 재방문 시 복원 (try/catch로 감쌀 것). 예전에 저장된 중간값은 가까운 끝으로 복원.

### 입력 우선순위
- 포인터가 레버 영역 안이면 레버가 우선. 리퀴드 글래스 구슬 드래그와 충돌하지 않게.
- 레버 드래그 중에는 자수(스티치)가 놓이지 않는다.

### 접근성
- `role="slider"`, `aria-valuemin="0"`, `aria-valuemax="100"`, `aria-valuenow`, `aria-label` 지정.
- 키보드: 두 자리 스위치로 동작. →/↑/End = 사이트맵, ←/↓/Home = 메인, Enter/Space = 전환. (처음 지침의 5 단위 조절은 중간 정지 금지에 맞춰 바꿈)
- 터치 드래그 지원 (`touch-action: none`).

### 연결부
```js
function onLeverChange(value) {
  // value: 0 ~ 1
  // → 화면 회전판 (아래 "레버 연결 1 — 화면 회전판과 사이트맵")
}
```

### 레버 연결 1 — 화면 회전판과 사이트맵
레버를 돌리면 상단 요소를 뺀 화면 전체가 레버와 함께 돌아가면서, 뒷면의 사이트맵 화면이 나타난다.
- **돌아가는 것 / 남는 것**
  - 회전판(`#world`) 안: 배경(+ 패턴·밝아짐·자수 캔버스), 하단 작가 소개, 물리 스테이지(천 · 줄 · 구슬), 사이트맵 면.
  - 회전판 밖(제자리): 상단 사이트명, 배색 프리셋 버튼, plan-draft 버튼, 레버 자신과 라벨, 펼쳐 보기 정보층, 페이지 이동 덮개.
- **회전**: 축 = 레버 피벗(왼쪽 `--lever-left`, 세로 중앙). 회전 각도 = value × 180°, 시계 방향 (레버가 도는 방향과 같음). 드래그 중에는 레버의 lerp를, 넘어갈 때는 레버의 스프링을 그대로 따라 돈다.
- **사이트맵 면**: 회전판 반대편에 180° 거꾸로 붙어 있어서, 회전판이 180° 돌면 똑바로 선다. 배경은 두 면이 함께 쓰는 + 격자 층과 화면 고정 바탕색 위에 투명하게 놓인다 (아래 "배경 연장").
  - 절반(90°) 전까지는 메인 면이 위, 넘어가면 사이트맵 면이 위로 올라온다.
  - 돌아가는 동안 메인 내용(배경 캔버스 · 작가 소개 · 천 · 줄 · 구슬)은 value 0.55 → 0.85에서 서서히 사라지고, 사이트맵 내용은 0.15 → 0.45에서 서서히 나타난다 (두 면이 투명해서 겹치는 부분이 비치지 않게).
- **배경 연장** (수정 요청 반영): 회전할 때 원래 화면 밖이던 영역에도 + 격자가 이어진다.
  - 바탕색과 가장자리 비네팅은 회전판 밖, 돌지 않는 `body` 배경으로 옮겼다 → 어느 각도에서도 화면 가장자리 그늘은 제자리.
  - + 격자는 회전판 안의 `#field` 층 하나로 옮겼다. 피벗을 중심으로 "피벗에서 가장 먼 화면 모서리까지 + 24px"를 반지름으로 하는 정사각형이라, 어느 각도로 돌아도 화면을 다 덮는다. 격자 위치는 화면 중앙 셀 (0,0) 기준 그대로라 밝아지는 + · 자수와 정확히 겹친다.
  - 메인 면(`#bg`)과 사이트맵 면은 배경 없이 투명.
- **사이트맵 내용** (사이트 지도 v2 요약, 링크)
  - Work — Collections / Swatch
  - Journal — Making / Research / Exhibition / Note
  - About — Bio / Statement / CV
  - Contact — Email / Inquiry
  - 아래에 "레버를 다시 세우면 메인으로 돌아가요" 안내, 그 아래 관리 페이지 숨은 입구 `admin` (13장).
  - 링크를 누르면 메인 메뉴와 같이 배경색 덮개 페이드 후 이동.
- **조작 잠금**
  - 조금이라도 돌아가면(value > 0.01) 메인 줄·구슬은 잡을 수 없다 (돌아간 화면에서 좌표가 어긋나지 않게). 물리는 계속 돈다.
  - 사이트맵 링크는 거의 다 돌았을 때(value > 0.97)만 누를 수 있고, 그 전에는 `inert` + `aria-hidden`으로 키보드·스크린리더에서도 숨긴다.
- 레버 자리는 저장되므로, 사이트맵을 연 채로 떠났다면 다음 방문 때도 사이트맵 면으로 시작한다.
- 모바일: 사이트맵은 2열, 레버 영역(106px)만큼 왼쪽을 비운다.

#### 구현 메모 (회전판)
- **구조**: `#world` = `position: fixed; inset: 0; z-index: 0` 상자. 안에 `#field`(+ 격자, z −2), `#bg`, `.corner.bl`(작가 소개), `#stage`, `#sitemap`. 원래 각자 `position: fixed`였던 요소들은 변형(transform)된 부모 안에서 그 부모 기준으로 배치되는데, `#world`가 화면 전체 크기라 위치는 그대로다. `will-change: transform`으로 회전을 GPU 합성에 맡긴다.
- **축 공유**: 레버 피벗 위치 `--lever-left`(48px, 모바일 24px)를 `:root` 변수로 올려, 레버·회전판·사이트맵 면이 같은 값을 쓴다. 회전판과 사이트맵 면 모두 `transform-origin: var(--lever-left) 50%`.
- **회전**: `onLeverChange(value)`가 `#world`에 `transform: rotate(value × 180deg)`만 바꾼다 (0이면 transform 제거). 물리 좌표·캔버스는 건드리지 않고 CSS로만 돌린다.
- **면 순서**: `#sitemap`은 `transform: rotate(180deg)`로 회전판 반대편에 붙어 있고 평소 `z-index: -1`. value ≥ 0.5이면 `#world.flip` → `z-index: 3`으로 맨 위.
- **페이드**: `onLeverChange`가 `#world`에 `--main-a`, `--map-a`(smoothstep)를 넣고, `#bg`·`.corner.bl`·`#ropes`·`#letters`·`#glass`와 `.sm-inner`가 이를 opacity로 쓴다. `#stage` 전체에 opacity를 주면 유리 구슬의 backdrop-filter가 스테이지 안만 비추게 되므로 요소마다 준다.
- **격자 층 크기**: `sizeField()`가 `sizeCanvas()`(시작·리사이즈) 때 `#field`의 위치·크기와 mask-position을 계산한다.
- **상태 클래스**: `#world.turned`(value > 0.01) → `#stage { pointer-events: none }`. 사이트맵은 value > 0.97일 때만 `inert = false`, `aria-hidden="false"`.
- **사이트맵 링크**: 클릭 시 `#page-fade` 덮개를 켜고 0.35초 뒤 이동 (메인 메뉴 전환과 같음). 새 탭 열기 키(Ctrl/⌘/Shift)는 그대로 둔다.
- **유리 구슬 굴절**: 구슬과 배경이 같은 회전판 안에 있어 backdrop-filter가 회전 중에도 그대로 작동한다.

### 구현 메모
- 코드의 "좌측 회전 레버" 섹션에 분리. 조절값은 `LEVER` 상수 (`hit` 96px, `follow` 0.25, `snap` 60°, `spring` 0.09, `damping` 0.78, `bounce` 0.3, `storageKey` `"lever"`).
- 마크업: `#lever` 안의 SVG 하나 (직선 `.lv-line`, 궤적 점 `.lv-track` 3개, 곡선 화살표 `.lv-arrow`, 피벗 점 `.lv-pivot`). 색은 `currentColor` = `--lever`라 배색 프리셋을 따른다.
- **잡기 영역**: `#lever`는 피벗을 중심으로 한 192×192 상자에 `clip-path: circle(96px)`. 원 안만 레버가 포인터를 받고, 원 밖은 아래의 줄·구슬이 그대로 받는다. 레버는 물리 스테이지 위 레이어(`z-index: 4`)라 원 안에서는 항상 레버가 우선이고, 이벤트가 스테이지로 내려가지 않는다.
- **자수와의 관계**: 스티치는 구슬을 잡았을 때만 놓이므로, 레버를 잡는 동안에는 구조적으로 놓이지 않는다 (자수 코드는 수정하지 않음).
- **각도**: 피벗 기준 `atan2(dx, -dy)` → 12시 0°, 시계 방향 +. 왼쪽 반원(음수)은 위쪽이면 0°, 아래쪽이면 180°로 붙인다.
- **움직임**: 레버 전용 rAF 루프 하나. 드래그 중에는 목표 각도(`lever.target`)를 lerp로, 확정(`commitLever`) 뒤에는 스프링으로 따라가고 끝(0°/180°)에서 튕긴다. 도착하면 루프를 멈춘다. 매 프레임 `onLeverChange(angle / 180)`과 `aria-valuenow`(0~100) 갱신. `prefers-reduced-motion`이면 바로 이동.
- **넘어가기 판정**: `dragLeverTo(deg)` — 쉬는 자리(`lever.rest`)가 0이면 deg ≥ 60에서, 180이면 deg ≤ 120에서 `commitLever(반대편)`. 손을 떼면 `commitLever(lever.rest)`(되돌아감).
- **저장**: 확정할 때마다 `localStorage.lever`(0 또는 1)에 저장하고, 페이지를 열 때 복원한다.
- **레버 영역 비우기**: 작품 걸이 배치(`hangLayout()`)가 `leverZone()`만큼 왼쪽을 비우고 나머지 폭을 3칸으로 나눈다. 데스크톱 155px(48 + 77 + 여백 30), 모바일 106px(24 + 58 + 여백 24). 모바일은 화면이 좁아 레버 크기에 맞춰 줄였다.

### 확인
- [ ] 수직으로 서 있다가 드래그하면 오른쪽 반원을 따라 회전한다
- [ ] 0°~180° 밖으로는 넘어가지 않는다
- [ ] 화면 크기가 바뀌어도 왼쪽 간격이 유지된다
- [ ] 구슬 · 천 드래그와 서로 간섭하지 않는다
- [ ] 레버 위 SITEMAP / MAIN 라벨을 눌러도 전환된다
- [ ] 키보드로도 조절된다 (→/↑/End 사이트맵, ←/↓/Home 메인, Enter/Space 전환)
- [ ] 60° 이상 돌리면 자동으로 끝까지 넘어가고, 그 전에 놓으면 되돌아간다 (중간에 멈출 수 없다)
- [ ] 회전 중에도 화면 전체에 + 격자 배경이 이어진다
- [ ] 기존 기능이 그대로 동작한다
- [ ] 레버를 돌리면 상단 요소를 뺀 화면이 함께 돌고, 끝까지 돌리면 사이트맵이 똑바로 선다
- [ ] 사이트맵 링크로 각 페이지에 이동하고, 레버를 세우면 메인으로 돌아온다

### 주소와 노출
- `admin.html` — 메뉴·푸터 등 눈에 띄는 곳에는 링크하지 않는다. `<meta name="robots" content="noindex, nofollow">`.

### 로컬 미리보기 모드 (3단계 전)
- 저장소는 `assets/data.js`의 `Store`. 처음엔 `SAMPLE`을 복사해 쓰고, 관리 페이지에서 저장하면 이 브라우저의 `localStorage["portfolio-local-db-v1"]`에 전체가 저장된다.
- **같은 브라우저**로 사이트를 열면 사이트도 같은 `Store`를 읽으므로 고친 내용이 바로 보인다. 다른 사람·다른 기기에는 여전히 `SAMPLE`이 보인다.
- 상단 배너로 모드를 알리고, 두 가지 도구를 둔다.
  - **JSON 내보내기**: 저장된 전체(표 전부)를 `portfolio-YYYY-MM-DD.json`으로 받는다 → 3단계에서 Supabase로 옮길 때 사용.
  - **예시 데이터로 되돌리기**: 로컬 저장을 지운다 (확인 창).

- 사이트 문의 폼은 로컬 모드에서도 **저장하지 않는다** (방문자 브라우저에만 남으면 문의가 사라지므로) — 계속 메일 앱으로 대체. 문의함에는 예시 2건만 보인다.

## 14. Supabase 연결 (준비 완료 — 설정만 채우면 됨)
> 사이트·관리 페이지는 Supabase를 전제로 다 만들어 두었다. 연결은 "SQL 실행 → 관리자 계정 → 설정 두 칸" 세 가지로 끝난다.

### 모드
- `assets/data.js` 맨 위 `SUPABASE.url`, `SUPABASE.anonKey`가 **비어 있으면 로컬 미리보기**, **채우면 Supabase** 모드.
- 모드가 바뀌어도 페이지·관리 화면 코드는 그대로 (`DB.*` 안쪽만 모드별로 동작).
- Supabase 라이브러리(`@supabase/supabase-js@2.45.4`, jsdelivr)는 Supabase 모드일 때만 불러온다.

### 연결 순서
1. Supabase에서 프로젝트를 만든다.
2. 대시보드 → SQL Editor에 `supabase/schema.sql` 전체를 붙여 넣고 실행 (다시 실행해도 안전).
3. 관리자 계정 (schema.sql 맨 아래 "관리자 등록")
   1. Authentication → Users → Add user: 내 이메일 + 비밀번호.
   2. 가입 허용(Allow new users to sign up)을 끈다.
   3. `insert into public.admin_users (user_id) select id from auth.users where email = '내 이메일';` 실행.
4. Project Settings → API의 **Project URL**과 **anon public** 키를 `assets/data.js`의 `SUPABASE.url`, `SUPABASE.anonKey`에 넣고 커밋·푸시. (`service_role` 키는 절대 넣지 않는다)
5. 사이트맵의 `admin` → 로그인 → 상단 **JSON 가져오기**로, 로컬 미리보기에서 **JSON 내보내기** 해 둔 파일을 올린다. 사진(data URL)은 자동으로 Storage에 올라가 주소로 바뀐다.
6. 사이트를 열어 확인 (예시 데이터 대신 내 내용이 보이면 끝).

### 관리 페이지 로그인 (입장 전 입력)
- `admin.html`을 열면 먼저 **관리자 로그인**(이메일 + 비밀번호) 화면. 통과해야 편집 화면이 열린다.
- Supabase Auth `signInWithPassword`로 확인하고, 이어서 서버 함수 `is_admin()`으로 **관리자로 등록된 계정인지** 확인한다. 아니면 바로 로그아웃하고 "관리자로 등록된 계정이 아니에요".
- 로그인은 브라우저에 유지되고(자동 갱신), 상단 **로그아웃**으로 끝낸다.
- **보호는 서버가 한다**: 화면을 가리는 것은 편의일 뿐이고, 모든 쓰기·비공개 읽기·사진 올리기는 RLS가 `is_admin()`인 계정에만 허용한다. 비밀번호나 검사 코드는 사이트 소스에 없다.
- 로컬 미리보기 모드에서는 로그인 칸이 비활성으로 보이고, 그 이유와 함께 "로컬 미리보기로 들어가기" 버튼만 있다 (이 모드는 이 브라우저에만 저장되므로 실제 사이트에 영향이 없다).

### 권한 정리 (`supabase/schema.sql`)
| 대상 | 방문자(anon) | 관리자(로그인 + admin_users) |
|---|---|---|
| collections · works · journal_posts · cv_items | `is_public = true`만 읽기 | 모두 읽기·쓰기 |
| site_settings | 읽기 | 읽기·쓰기 |
| inquiries | 쓰기(insert)만 | 읽기·처리·삭제 |
| Storage `portfolio` | 읽기 | 올리기·바꾸기·지우기 |
| admin_users | 접근 불가 | 접근 불가 (SQL Editor에서만) |
- `is_admin()`은 `security definer` 함수로 `admin_users`에 내 `auth.uid()`가 있는지만 돌려준다.
- `cv_items`, `inquiries`의 숫자 id는 서버가 매긴다(`generated by default as identity`). 관리 페이지는 새 항목에 id를 보내지 않고, 저장 결과로 받은 id를 쓴다.

### Supabase 모드에서 달라지는 것
- **사이트 읽기**: 표에서 직접 읽는다. 실패하면 빈 목록으로 그린다(사이트가 멈추지 않게).
- **사이트 설정**: 받을 때마다 `localStorage["portfolio-settings-cache"]`에 저장해, 다음 방문의 첫 화면을 기다림 없이 그린다. 최신 값을 받으면 로고·푸터·About·Contact·Journal 문구·메인 작가 소개를 다시 채운다(`siteReady`, `applyMainSettings`). 메인 HTML에는 이름 등을 미리 적어 두지 않는다(예시 이름이 잠깐 보이지 않게).
- **문의 폼**: `inquiries`에 저장되고 "보냈어요"가 뜬다. 관리 페이지 문의함에 쌓인다.
- **사진**: 긴 변 2000px · 1MB 이하로 줄여 Storage `portfolio/폴더/시각.jpg`에 올리고 공개 URL을 저장.
- **관리 페이지**: '예시 데이터로 되돌리기'는 숨기고, 'JSON 가져오기'와 '로그아웃'을 보인다. 'JSON 내보내기'는 Supabase의 모든 표를 받는다(백업).
