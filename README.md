# my-portfolio
# 포트폴리오 메인 인덱스 화면 UI/UX · 구현 지침

> 사이트의 목적, 대상 독자, 메뉴별 내용 등 기획은 [plan-draft.html](plan-draft.html)에 정리되어 있다. 이 문서는 화면 UI/UX와 구현 지침만 다룬다.

## UX 원칙
- **첫 화면은 놀이, 안쪽은 읽기.** 메인은 만지고 당겨보는 재미로 시선을 잡고, 하위 페이지는 군더더기 없이 정돈해 내용이 잘 읽히게 한다.
- **모바일 우선.** 핵심 독자인 관람객이 휴대폰으로 접속하므로 모바일 화면을 기준으로 설계하고 데스크톱으로 확장한다.
- **설명 없이 쓸 수 있게.** 줄을 당기면 열린다는 사실을 화면 안의 힌트와 피드백(색 변화)만으로 알 수 있어야 한다.

## 0. 작업 범위
- 목표: 포트폴리오 사이트의 **메인 인덱스 화면 1개**만 구현한다.
- 하위 페이지는 11장 참고 (메인은 단일 `index.html`, 하위 페이지는 공통 `assets/`를 공유).
- 결과물: 단일 파일 `index.html` (HTML + CSS + JS 인라인).
- 외부 라이브러리는 CDN으로만 로드 (물리엔진: Matter.js 권장 — cdnjs).
- 배포: GitHub 저장소 → GitHub Pages. 빌드 도구 사용하지 않음.
- Supabase: 이번 단계에서는 연결하지 않음. 단, 2단계에서 메뉴 데이터를 Supabase로 옮길 수 있도록 메뉴 데이터를 코드 상단의 설정 객체 하나로 분리해 둔다.

## 1. 화면 구성 개요
- 전체 화면(100vw × 100vh), 스크롤 없음. 화면 자체가 하나의 물리 공간.
- 요소는 3가지:
  1. 배경 (파란 단색 `--bg` + 화면 전체에 촘촘히 깔린 미세한 `+` 패턴, 구슬 주변만 하얗게 밝아짐 — 5-2 참고)
  2. 천장에 매달린 **메뉴 줄 N개** (세로 타이포)
  3. 상단에서 떨어지는 **원형 리퀴드 글래스 구슬 1개**
- 화면 네 변(천장 제외 시 좌/우/바닥 + 천장 포함)에 보이지 않는 벽을 두어 물체가 화면 밖으로 나가지 않게 한다.

## 2. 설정 객체 (코드 최상단에 분리)
```js
const CONFIG = {
  menus: [
    { label: "WORK",    href: "work.html" },
    { label: "JOURNAL", href: "journal.html" },
    { label: "ABOUT",   href: "about.html" },
    { label: "CONTACT", href: "contact.html" },
  ],
  rope: {
    segments: 12,          // 줄 마디 수
    segmentLength: 14,     // 마디 길이(px)
    stiffness: 0.9,        // 마디 연결 강성
    damping: 0.05,         // 흔들림 감쇠
    pullThreshold: 160,    // 기본 위치에서 이만큼(px) 아래로 당기면 페이지 열림
  },
  glass: {
    radius: 70,            // 구슬 반지름(px), 모바일에서는 화면 폭 비례로 축소
    restitution: 0.4,      // 바닥 튕김 정도
    density: 0.002,
  },
  gravity: 1,
};
```
- 메뉴명은 이 배열만 수정하면 줄 개수와 글자가 자동 생성되어야 한다.

## 3. 메뉴 줄 + 세로 타이포
- 각 메뉴마다 화면 상단(천장)에 고정점 1개를 둔다. 고정점은 가로로 균등 배치 (메뉴 수에 따라 자동 간격).
- 고정점에서 아래로 줄(rope)이 수직으로 늘어진다.
  - 줄 = Matter.js 원형 소형 바디 여러 개를 `Constraint`로 사슬 연결 (Composites.chain 사용 가능).
  - 줄은 화면에 얇은 선으로 렌더링 (canvas 또는 SVG path, 마디를 부드러운 곡선으로 연결).
- 줄 끝에 메뉴명이 **세로 타이포**로 이어진다.
  - 글자 하나 = 물리 바디 하나. 글자들도 줄처럼 서로 Constraint로 연결되어, 줄과 글자가 하나의 사슬처럼 움직인다.
  - 글자는 위→아래 세로로 쌓인 배열. 각 글자 바디의 위치·회전값을 DOM 요소(또는 canvas 텍스트)에 매 프레임 동기화.
  - 폰트: **Pretendard** (`https://cdn.jsdelivr.net/gh/orioncactus/pretendard/dist/web/static/pretendard.css`), `font-weight: 300`. 파란 바탕에서 흰 글자가 뭉개지지 않도록 200은 쓰지 않는다.
  - 색은 `--text`(흰색). `document.fonts.ready` 이후 글자 바디를 생성한다.
  - 줄 선 색은 `--rope`.
- **비즈발(구슬발) 스타일**: 글자를 실에 꿴 구슬처럼 보이게 한다.
  - 글자 크기는 화면 높이에 비례하는 기본값의 **절반** (`BEAD.size: 0.5`). 글자 물리 바디도 함께 작아진다.
  - 글자 사이를 넓게 띄우고, **그 간격에도 실이 이어진다.** 간격은 실 마디 3개 길이의 80% (`BEAD.gapSegs: 3`, `BEAD.gapScale: 0.8`).
  - 글자 사이 실도 줄과 같은 원형 마디 바디로 만들어 구슬과 충돌한다 → 구슬이 글자 사이 틈으로 빠지지 않는다.
  - 실은 글자를 위→아래로 꿰뚫고 지나가도록 그리고(글자는 실 위 레이어), 마지막 글자 아래에 짧은 꼬리와 작은 매듭 점을 둔다.
  - 글자가 작아진 만큼 잡기 영역을 글자 중심에서 `BEAD.hitPad`(18px)만큼 넓혀 모바일에서도 잡기 쉽게 한다.
  - 가장 긴 메뉴(줄 + 글자 + 글자 사이 실)가 화면 높이의 약 85% 안에 들어오도록 글자 크기를 제한한다.
- 인터랙션:
  - 글자 아무거나 마우스/터치로 잡고 드래그 → 줄 전체가 당겨지며 자연스럽게 늘어지고 흔들림.
  - 놓으면 진자처럼 흔들리다 감쇠되어 원위치로 돌아옴.
  - **당김 판정**: 드래그 중 해당 메뉴 사슬의 마지막 글자가 기본 위치 대비 `pullThreshold` 이상 아래로 내려간 상태에서 손을 놓으면 → 해당 메뉴의 페이지 열림.
    - 열림 연출: 줄이 '툭' 끊기는 효과(고정점 Constraint 제거 → 글자들이 바닥으로 떨어짐) 후 화면 전환.
    - `href`가 페이지 주소면: 줄이 끊긴 뒤 화면을 배경색으로 덮는 페이드(0.35초) 후 해당 하위 페이지로 이동 (11장).
    - `href`가 `#`으로 시작하면: 화면 전체에 "준비 중: {label}" 오버레이 후 닫기 버튼으로 복귀 (복귀 시 줄 재생성). 아직 페이지가 없는 메뉴용.
  - 임계값 근처에서는 줄 색이나 글자 투명도를 살짝 바꿔 "더 당기면 열린다"는 피드백 제공.

## 4. 리퀴드 글래스 구슬
- 페이지 로드 직후 화면 상단 밖(또는 상단 근처)에서 생성되어 중력으로 **바닥까지 떨어짐**, 약하게 튕기고 멈춤.
- 물리: Matter.js 원형 바디. 바닥/좌우 벽과 충돌.
- 드래그: 구슬을 **클릭(터치) 후 홀드한 상태로 드래그**하면 화면 내 자유 이동.
  - 위치를 직접 덮어쓰지 말고 `MouseConstraint`(스프링 방식)로 끌어서, 이동 중에도 충돌 판정이 유지되게 할 것.
  - 놓으면 그 순간의 속도로 던져지고 다시 중력 적용.
  - 터널링(빠르게 움직일 때 줄을 통과하는 현상) 방지: 엔진 업데이트를 프레임당 여러 번 서브스텝으로 나누고, 구슬 최대 속도를 제한.
- 충돌 규칙:
  - 구슬이 줄·글자 바디와 부딪히면 → 줄이 밀려나며 흔들리는 물리 반응.
  - 구슬은 줄/글자 안으로 **절대 파고들지 않음**. 줄 위에 놓거나 걸치면 줄이 구슬 모양대로 휘어지며 구슬이 줄 **바깥에 걸쳐진** 상태로 유지되어야 함 (구슬이 줄에 얹혀 매달려 있을 수 있음).
  - 이를 위해 줄 마디 바디 간격을 촘촘하게(마디 반지름 ≥ 간격의 절반) 설정해 틈이 생기지 않게 한다.
  - 구슬과 줄 마디끼리는 충돌, 같은 줄의 마디끼리는 충돌하지 않도록 collisionFilter 그룹 설정.
- 드래그 우선순위: 포인터 아래에 구슬과 글자가 겹치면 구슬을 우선 잡는다.

## 5. 리퀴드 글래스 렌더링
- 구슬은 물리 바디 위치에 동기화되는 원형 DOM 요소로 렌더링.
- 스타일 구성:
  - `backdrop-filter: blur(6~10px) saturate(...)` 로 뒤 배경/글자가 비침. 파란 배경에 맞춰 블러를 약하게 낮춰, 뒤의 `+` 패턴이 흐려져 사라지지 않고 **휘어져 보이게** 한다.
  - 반투명 흰색 배경 `--glass-tint` + 얇은 흰색 테두리 `--glass-border`.
  - inset box-shadow로 상단 가장자리 흰색 하이라이트, 하단은 은은한 반사광. 바깥 그림자는 `--bg-dark` 저투명도.
  - 가장자리 굴절: SVG `feTurbulence`/`feDisplacementMap` 필터를 backdrop에 적용해 뒤 배경과 `+` 패턴이 가장자리에서 휘어 보이게. 지원하지 않는 브라우저(Safari, Firefox)에서는 일반 블러로 자연스럽게 대체되도록 기능 감지 후 분기 — 이때도 블러 + 구슬 주변의 밝아진 패턴으로 유리의 존재감이 느껴져야 한다.
  - 구슬 이동 속도에 따라 하이라이트 위치가 이동 방향 반대쪽으로 살짝 밀리는 효과 (선택).
  - 드래그 중에는 구슬이 살짝 커지거나 눌린 듯 변형(scale) — 물방울 같은 말랑함.
- 구슬이 글자 위로 지나가면 글자가 굴절·흐림 처리되어 보여야 함 (글자가 구슬 뒤 레이어에 있어야 backdrop-filter가 적용됨 → z-index: 배경색 < `+` 패턴(dim, bright) < 줄/글자 < 구슬).

## 5-1. 컬러 (파란 배경 + 흰 글자 + 노란 포인트)
> 디자인 수정 원칙: 물리 로직, 인터랙션, 충돌, 당김 판정 등 **기능 코드는 수정하지 않는다.** 색상·폰트·배경 레이어만 수정/추가하며, 모든 색상은 `:root` CSS 변수로 관리한다.

### 메인 컬러 3가지
| 역할 | 색상 | 변수 | 쓰임 |
|---|---|---|---|
| 배경 블루 | `#0356fc` | `--bg` | 화면 배경 (가장자리 비네팅은 `--bg-dark` `#0238a8`) |
| 화이트 | `#ffffff` | `--text` | 메뉴 타이포, 줄, + 패턴, 유리 하이라이트, 오버레이 텍스트 |
| 포인트 옐로 | `#fcad03` | `--accent` | 줄 당김 피드백 — 임계값에 가까워지면 글자·줄이 이 색으로 바뀜. 하단 작가 소개의 역할·이메일·소개 문구, 이름 외곽선 |

- **하단 작가 소개**: 이름은 흰색 글자에 노랑(`--accent`) 얇은 외곽선(1.5px stroke를 글자 뒤에 칠해 바깥쪽만 보이게). 그 외 텍스트(역할, 이메일, 소개 문구)는 노랑.

```css
:root {
  --bg: #0356fc;
  --bg-dark: #0238a8;
  --text: #ffffff;
  --accent: #fcad03;                         /* 줄 당김 피드백 */
  --rope: rgba(255, 255, 255, 0.5);
  --plus-dim: rgba(255, 255, 255, 0.12);    /* 평소 + 패턴 */
  --plus-bright: rgba(255, 255, 255, 0.95); /* 구슬 근처 + 패턴 */
  --glass-tint: rgba(255, 255, 255, 0.12);
  --glass-border: rgba(255, 255, 255, 0.6);
}
```
- 배경은 `--bg` 단색 기반. 화면 가장자리만 `--bg-dark`로 아주 약한 비네팅(radial-gradient) 허용.
- 메뉴 타이포, 줄, 오버레이 텍스트 모두 흰색 계열.

## 5-2. + 패턴 배경
### 구성
- 화면 전체에 `+` 기호를 촘촘한 격자로 배치.
  - 간격: 모든 화면에서 24px (자수 격자와 공유하므로 모바일도 동일)
  - 격자 기준점은 **화면 중앙**. 중앙 셀이 (0,0)이고, 각 셀의 `+` 중심 = 화면 중앙(픽셀 중앙 정렬) + (col, row) × 24px.
  - `+` 크기 7px, 선 두께 1px. 폰트 문자가 아닌 선 2개로 그려서 선명하게.
- 평소에는 `--plus-dim` 투명도로 거의 안 보이게 깔려 있다.
- 원형 글라스 구슬의 **중심 위치를 기준으로 반경 안의 `+`가 하얗게 밝아지면서 크기도 커진다.**
  - 범위: 구슬 반지름의 약 2.5배
  - 밝기: 중심에서 멀어질수록 부드럽게 dim으로 감소 (smoothstep 감쇠, 경계가 딱 끊기지 않게)
  - **크기: 밝기와 같은 smoothstep 값으로 함께 변한다.** 중심에서 최대 약 2.2배(7px → 약 15px), 범위 가장자리에서 원래 크기. 선 두께도 1px → 약 1.6px로 살짝 굵어진다. 크기 변화의 부드러움은 색 변화와 같은 정도로 맞춘다.
  - 구슬이 움직이면 빛·확대 영역이 따라 이동. 구슬 위치를 그대로 쓰지 않고 lerp(약 0.15)로 살짝 늦게 따라오게 해서 잔상처럼 부드럽게.

### 구현 방식 (성능 우선)
- 레이어 2장을 겹친다:
  1. **dim 레이어**: `--plus-dim` 색의 `+` 패턴 (SVG 타일을 mask-image로 반복, `-webkit-mask-image` 함께 지정)
  2. **bright 레이어**: `<canvas>` 1장. 구슬 주변 범위 안의 `+`만 `--plus-bright` 색으로, 거리에 따른 투명도·크기를 적용해 그린다.
- bright 레이어는 범위 안의 `+`만 그리고(데스크톱 기준 약 200개), 지난 프레임에 그린 영역만 지운다. 구슬과 빛 영역이 멈춰 있으면 다시 그리지 않는다.
- 두 레이어의 격자 위치가 정확히 일치해야 한다. dim 레이어의 mask-position을 JS가 `--grid-ox`, `--grid-oy`로 화면 중앙 기준에 맞추고, canvas도 같은 기준점으로 `+`를 그린다.
- 조절값은 코드 상단 `GLOW` 상수: `range`(범위 배수), `follow`(lerp), `maxScale`(최대 확대 배율).

### 레이어 순서 (z-index)
- 배경색 < `+` 패턴(dim, bright) < 자수 캔버스(10장) < 줄·메뉴 타이포 < 리퀴드 글래스 구슬
- `+` 패턴이 구슬 **뒤**에 있어야 backdrop-filter와 굴절 필터로 `+`가 유리 안에서 휘어 보인다.
- `+` 패턴 레이어는 `pointer-events: none`.

## 6. 반응형 / 접근성 / 성능
- 리사이즈 시 벽 위치, 줄 고정점, 구슬 크기 재계산 (디바운스).
- 모바일 터치 드래그 지원, 드래그 중 페이지 스크롤/새로고침 제스처 방지 (`touch-action: none`).
- `prefers-reduced-motion` 사용자는 물리 대신 정적인 세로 메뉴 + 정지된 구슬 표시.
- 키보드/스크린리더용으로 시각적으로 숨긴 `<nav>` 링크 목록을 별도로 제공.
- 탭이 비활성일 때 엔진 정지. 60fps 목표, 렌더링은 requestAnimationFrame 1개 루프에서 처리.

## 10. 십자수 자수 방명록

### 원칙
- 기존 물리, 메뉴 줄, 당김 판정, 리퀴드 글래스, + 패턴 밝아짐 효과는 **수정하지 않는다.**
- 자수 기능은 별도 모듈(함수/섹션)로 분리해서 추가한다.
- 1단계 완료 후 브라우저에서 확인 → 커밋 → 2단계 진행.

### 컨셉
화면에 깔린 + 격자를 십자수 천(아이다 천)으로 보고, 리퀴드 글래스 구슬을 바늘처럼 끌고 다니면
지나간 자리의 + 가 흰 실로 놓인 X 스티치로 바뀐다. 방문자들이 남긴 자수가 쌓여 하나의 천이 된다.

### 1단계: 화면 위 자수 (로컬)

#### 격자 기준
- 자수 격자는 기존 + 패턴 격자와 **정확히 일치**해야 한다.
- 모든 화면 크기에서 격자 간격을 24px로 통일 (기존 모바일 20px 설정을 24px로 변경).
- 셀 좌표는 **화면 중앙을 (0,0)으로 하는 정수 (col, row)** 로 관리한다.
  → 화면 크기가 달라도 같은 자수가 같은 자리에 보이게 하기 위함. 화면 밖 셀은 그리지 않을 뿐 데이터는 유지.
- + 패턴의 background-position도 화면 중앙 기준으로 맞춰서 셀 좌표와 어긋나지 않게 할 것.

#### 스티치가 놓이는 조건
- 사용자가 구슬을 **홀드-드래그하는 동안에만** 놓인다. (낙하·굴러감·던진 후 이동 중에는 놓이지 않음)
- 구슬 중심 기준 반경 = 구슬 반지름 × 0.35 안에 들어온 셀이 스티치 대상.
- 속도 반영 (손맛):
  - 느리게 움직이면 반경 안 셀이 모두 채워짐
  - 빠르게 움직일수록 확률적으로 건너뛰어 듬성듬성해짐 (속도에 비례해 채움 확률 감소, 최소 20%)
- 프레임 사이 이동 거리가 길면 이전 위치~현재 위치를 선형 보간해서 경로 중간 셀도 판정 (빠르게 끌어도 선이 끊기지 않게).
- 이미 스티치된 셀은 다시 놓이지 않음.

#### 스티치 표현
- 별도 `<canvas>` 레이어를 추가. 레이어 순서:
  배경색 < + 패턴(dim/bright) < **자수 캔버스** < 줄·메뉴 타이포 < 리퀴드 글래스 구슬
  → 자수가 구슬 뒤에 있으므로 구슬 안에서 자수도 굴절되어 보여야 한다.
- 스티치 = 셀 안에 그리는 X 모양 실 두 가닥.
  - 먼저 셀 아래의 + 를 가리도록 배경색(`--bg`)으로 작은 사각형을 칠한 뒤 X를 그린다.
  - 크기: 셀의 약 70%, 선 두께 1.5px, 선 끝 둥글게 (lineCap: round), 색 `--text`(흰색).
  - 실 느낌: 각 가닥의 끝점을 ±0.6px 랜덤 흔들림, 투명도 0.85~1 랜덤. 실 가운데가 살짝 밝고 가장자리가 어두운 미세한 그라데이션이면 더 좋음.
  - 손바느질 순서처럼 `/` 를 먼저 그리고 이어서 `\` 를 그리는 애니메이션 (각 약 80ms).
- 캔버스는 devicePixelRatio 대응. 새 스티치만 증분으로 그리고, 리사이즈 시에만 전체 다시 그림.
- 스티치 데이터는 메모리의 Map(`"col,row"` → { col, row, createdAt })에 보관.
- 기존 + 밝아짐 효과는 자수 위에도 자연스럽게 겹쳐 보여도 무방.
- **불투명도 최대치 80%**: 자수(실과 + 가림 사각형 포함) 전체를 최대 0.8 불투명도로 그려, 겹친 메인 화면 텍스트가 묻히지 않게 한다 (`STITCH.opacity`).
- **약 10초 뒤 사라짐**: 스티치는 놓인 지 6초부터 4초 동안 서서히 옅어져 10초에 사라진다 (`STITCH.lifeMs`, `STITCH.fadeMs`). 사라진 셀은 Map에서 지워져 다시 수놓을 수 있다.

#### 기타
- `prefers-reduced-motion`이면 그리기 애니메이션 없이 즉시 표시.
- 자수는 물리에 영향을 주지 않는다 (충돌 바디 없음).

#### 구현 메모
- 코드의 "십자수 자수 방명록" 섹션에 분리. 조절값은 `STITCH` 상수 (`reach`, `size`, `width`, `jitter`, `fastSpeed`, `minFill`, `strokeMs`).
- 채움 확률 = max(0.2, 1 − 프레임당 이동량 / 40px). 한 프레임 안에서 셀마다 한 번만 판정한다.
- 실의 흔들림·투명도 난수는 셀 좌표로 고정(시드)해서, 리사이즈로 다시 그려도 같은 모양이 나온다.
- 실 그라데이션은 같은 선을 두 번(옅고 두꺼운 가장자리 → 밝고 얇은 가운데) 그려 표현한다.

#### 1단계 확인
- [ ] 구슬을 드래그할 때만 지나간 자리에 X 스티치가 놓인다
- [ ] 천천히 끌면 촘촘, 빠르게 끌면 듬성듬성
- [ ] 스티치가 + 격자와 정확히 같은 위치에 놓인다 (리사이즈 후에도)
- [ ] 구슬 안에서 스티치가 유리에 굴절되어 보인다
- [ ] 스티치가 약 10초 뒤 서서히 옅어지며 사라진다
- [ ] 스티치와 겹쳐도 메인 화면 텍스트가 읽힌다 (자수 불투명도 최대 80%)
- [ ] 기존 기능이 전부 그대로 동작한다

|---|---|

### 공통 요소 (모든 하위 페이지)
- 디자인 언어 유지: 파란 배경(#0356fc), 흰 글자, Pretendard 300, 미세한 + 격자 배경
  - + 격자는 메인과 같은 24px 타일, 같은 화면 중앙 기준 (`--grid-ox/oy`). 파란 바탕 흰 글자에 200 굵기는 쓰지 않는다.
  - 강조(현재 메뉴, 호버, 카테고리, 이력 구분)는 포인트 옐로 `--accent`.
- 좌측 상단: 메인으로 돌아가기 (메인으로 가면 줄이 다시 매달리는 연출)
  - `site.js`가 메인으로 가는 링크 클릭 시 `sessionStorage.rehang = "1"`을 남긴다.
  - 메인은 시작할 때 이 값을 읽고 지운 뒤, 모든 줄을 같은 각도(최대 약 20°, 줄 간격의 80%를 넘지 않게)로 들어 올린 채 시작해 진자처럼 흔들리며 내려오게 한다. 마디 사이 거리는 그대로라 물리 제약이 깨지지 않고, 모든 줄이 같은 방향이라 서로 겹치지 않는다.
- 우측 상단: 다른 메뉴로 이동하는 작은 텍스트 네비게이션 (Work · Journal · About · Contact). 현재 페이지는 `aria-current="page"` + 노랑 밑줄.
- 하단: 이메일, Instagram, © 이름 연도
- 페이지 진입: 메인에서 줄이 끊긴 직후 해당 페이지로 자연스럽게 페이드 전환
  - 메인: 줄 끊김(0.65초) → 배경색 덮개 페이드인(0.35초) → 이동.
  - 하위 페이지: 본문이 0.5초 페이드인으로 시작. 사이트 안 링크 이동은 0.28초 페이드아웃 후 이동.
  - 뒤로가기(bfcache)로 돌아오면 덮개를 해제한다. `prefers-reduced-motion`이면 페이드 없이 바로 이동.

### 페이지별 구현 메모
- **Work 목록**: 섹션은 하나만, 기법은 여러 개 선택. 기법은 선택한 것 중 **하나라도** 쓴 작업을 보여준다 (OR). 필터 상태는 주소(`?section=projects&tech=weave,print`)에 남아 공유·새로고침 시 유지된다.
- **Work 상세**: `?id=`로 찾는다. 이전/다음은 목록 정렬 순서(`sort`) 기준. 과정·갤러리가 비어 있으면 그 섹션을 숨긴다. 기법 태그를 누르면 그 기법으로 거른 목록으로 이동.
- **Journal**: 최신순(`date` 내림차순). 카테고리 필터는 `?category=`로 유지. 본문은 블록 배열(`{type:"p", text}` / `{type:"img", src, caption}`).
- **About**: 이력은 구분(학력·전시·수상·경력/활동)별로 묶고, 각 구분 안은 연도 역순. `SITE.cvUrl`이 없으면 CV 버튼은 '준비 중'으로 비활성.
- **Contact**: 이메일을 누르면 클립보드 복사 후 메일 앱을 연다. 문의 폼은 이름·이메일 형식·내용을 검사한 뒤 `DB.submitInquiry`로 보낸다. 저장소 연결 전에는 작성 내용을 제목·본문에 채운 메일 앱으로 대체한다.
- **이미지 자리**: 이미지 주소가 없으면 X 스티치 무늬 상자(`.ph`)와 라벨로 표시한다. 데이터에 주소가 들어오면 같은 비율의 `<img>`로 바뀐다.
- 데이터를 HTML에 넣을 때는 항상 `esc()`로 이스케이프한다.

### 데이터 관리 (Supabase)
코드를 고치지 않고 내용을 추가할 수 있도록, 반복해서 늘어나는 데이터는 Supabase 테이블로 관리:
- `works`: 작업 (분류, 기법 태그, 소재 정보, 이미지 목록, 공개 여부, 정렬 순서)
- `journal_posts`: 저널 글 (카테고리, 본문, 이미지, 관련 작업 id, 공개 여부)
- `history`: About 이력 (구분, 연도, 내용, 정렬 순서)
- `inquiries`: Contact 문의 (insert만 허용, 조회는 대시보드에서 나만)
- `stitches`: 메인 자수 방명록 (10장 2단계)
- 이미지는 Supabase Storage 버킷에 저장

**현재 상태**: Supabase 연결 전. `assets/data.js`의 `SAMPLE`이 위 테이블과 같은 모양의 **예시 데이터**를 제공한다. 연결 시 `DB.*` 함수 안쪽만 테이블 조회로 바꾸면 페이지 코드는 그대로 쓸 수 있다.

| `DB` 함수 | 테이블 | 조건 |
|---|---|---|
| `DB.works()` / `DB.work(id)` | `works` | `published = true`, `sort` 오름차순 |
| `DB.posts()` / `DB.post(id)` | `journal_posts` | `published = true`, `date` 내림차순 |
| `DB.history()` | `history` | `year` 내림차순, 같은 해는 `sort` 오름차순 |
| `DB.submitInquiry(data)` | `inquiries` | insert만. 성공 시 `{ ok: true }` |

필드 모양 (예시 데이터 기준):
- `works`: `id, title, year, section('projects'|'swatch'), techniques[], summary, concept, materials{fiber, technique, size, tools}, cover, process[{step, image, text}], gallery[{src, caption, detail}], published, sort`
- `journal_posts`: `id, title, date, category, thumbnail, summary, body[], related_work_id, published`
- `history`: `id, kind('education'|'exhibition'|'award'|'activity'), year, text, sort`
- `inquiries`: `name, email, type('collab'|'commission'|'etc'), message`

### 제작 우선순위
1. 공통 레이아웃 (헤더, 푸터, 배경) — 모든 하위 페이지가 공유
2. Work 목록 + 상세 — 포트폴리오의 핵심
3. About — 이력 타임라인
4. Contact — 문의 폼
5. Journal 목록 + 상세

### 하위 페이지 확인
- [ ] 메인에서 줄을 끝까지 당겼다 놓으면 끊긴 뒤 해당 페이지로 페이드 전환된다
- [ ] 하위 페이지 좌측 상단으로 메인에 돌아가면 줄이 흔들리며 다시 매달린다
- [ ] 우측 상단 메뉴에 현재 페이지가 표시되고, 다른 메뉴로 이동할 수 있다
- [ ] Work 필터(섹션 1개 + 기법 여러 개)가 동작하고 주소에 남는다
- [ ] 상세 페이지의 이전/다음/목록 이동이 동작한다
- [ ] Contact 이메일 클릭 시 복사 + 메일 앱이 열린다
- [ ] 모바일 폭(390px)에서 가로 스크롤 없이 읽힌다
